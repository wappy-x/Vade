$ vade up --help
Start the engine without opening chat.

Examples:
  vade up
  vade up --context 262144 --output 16384
  VADE_CONFIG=cluster.conf vade up --sparks 2

Usage: vade up [OPTIONS]

Options:
  --fp4-local       Qwen3.8 Flash-Next FP4-Local (the default; optional)
  --fp8             Qwen3.8 Flash-Next FP8 on 2, 4 or 6 Sparks (older spelling:
                    --fp8-legacy): context 131072, output 65536 (or the context
                    if smaller), drafting depth 2; output limit up to 262144
  --sparks N        Number of Sparks; FP4 supports 1..24
  --hosts a,b       Machine names in cable order, separated by commas
  --replicas N      2..16 independent one-Spark FP4-Local servers behind a local
                    gateway
  --mtp N           Drafting depth 0..3; 0 turns drafting off (default: the
                    engine chooses)
  --context N       Context window in tokens, 4096..262144 (default 32768)
  --output N        Output limit in tokens, 1024..16384 (default 8192, or the
                    context if smaller)
  --chats N         Concurrent FP8 chats, 1..32 (controller)
  --memory-bytes N  Memory budget per rank, in bytes
  --cache-bytes N   FP8 retained prompt cache, in bytes; 0 disables it. Local
                    FP4 accepts only 0
  --fast-prompts    Older option, kept for scripts; it has no effect
  --dry-run         Show what would happen; change nothing

Notes:
  - Default: Qwen3.8 Flash-Next FP4-Local on one Spark.
  - Local up and launch start with context 32768 and output 8192 (or the context
    if smaller). They reuse saved limits. A memory refusal lowers a default or
    saved context to a smaller size from 32768, 16384, 8192 and 4096. The first
    size that starts is saved. A refused explicit --context is an error. Local
    --chats and positive --cache-bytes are refused; --cache-bytes 0 disables
    retention.
  - Controller FP4 defaults match local ones on any Spark count: context 32768,
    output 8192 (or the context if smaller). --context 262144 requests a larger
    context. The engine still sets the chat count from context and memory.
  - Controller FP4 checks and passes on --chats and --cache-bytes, but its
    engine does not use them: it admits chats from memory and uses its own
    prefix cache setting.
  - The engine chooses the drafting depth (MTP). On one FP4-Local Spark,
    concurrent chats can draft; the default request depth is 3 with strict
    verification. FP8 concurrent chats do not draft. A request with draft=plain
    turns drafting off; draft=strict asks for it when supported. --mtp sets the
    depth, and 0 turns drafting off.
  - Two FP4-Local Sparks run the tensor split, the only two-Spark path for
    FP4-Local: both Sparks work on every token. It needs RDMA, so vade up
    refuses SEQPAR_RDMA=0 (TCP) for two FP4-Local Sparks. FP8 on two Sparks
    keeps its ring and may use TCP.
  - FP8 needs an FP8 config such as cli/examples/vade.conf. In our checks, FP8
    gave the same token IDs on each Spark count, but 2 and 4 Sparks gave
    different IDs. See docs/benchmarks.md.
  - Spark counts above 2 require a current install and linked hosts in cable
    order.
  - VADE_GROUP=NAME selects a [group NAME] from the config: its hosts in rank
    order, its own ownership record and its own local_port. A group must be an
    arc of the cabling: each host is cabled to the next, in rank order; a
    closing cable is not needed, so any run of neighbors on a ring works. Set
    the same VADE_GROUP for status, chat, logs and down. Groups in one layout
    can run at the same time. See docs/eight-sparks.md.
  - --replicas N starts one independent one-Spark server on each of the first N
    machines (or the N --hosts) and a local gateway on local_port; replica
    tunnels use the next N local ports. Each replica uses the FP4 defaults
    above. Use it when the model fits one Spark and many chats run at once;
    answers are the same on every replica.
  - One Spark needs no fabric. Linked Sparks use RDMA by default. SEQPAR_RDMA=0
    selects TCP, except for two FP4-Local Sparks. Keep VADE_CONFIG and VADE_HOME
    consistent through chat, status and down.
  - Only a running compute app or power draw of at least 30 W makes a GPU busy;
    a stale utilization reading is reported and never blocks.
