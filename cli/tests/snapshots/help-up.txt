$ vade up --help
Start the engine without opening chat.

Examples:
  vade up inkling
  vade up inkling --bind 0.0.0.0:18080
  vade up inkling --context 1048576
  vade up
  vade up --sparks spark-a,spark-b,spark-c,spark-d
  VADE_CONFIG=cluster.conf vade up inkling --replicas 2

Usage: vade up [MODEL] [OPTIONS]

Options:
  MODEL                  Optional short alias: inkling (Inkling 2 Mini) or qwen
                         (Qwen3.8 FP4-Local)
  --fp4-local            Qwen3.8 Flash-Next FP4-Local (the default without
                         MODEL; optional)
  --fp8                  Qwen3.8 Flash-Next FP8 on 2 or 4 Sparks; 6 Sparks start
                         but are not covered (older spelling: --fp8-legacy):
                         context 131072, output 65536 (or the context if
                         smaller), drafting depth 2
  --sparks a,b           The Sparks as you type them after ssh, in any order.
                         Vade reads the cables and sets them up
  --sparks N             How many Sparks of your setup to start (1 or more)
  --link FROM:TO=ADDR    With --sparks a,b: FROM's own address on its cable to
                         TO, to override what Vade reads
  --hosts a,b            Machines of your config, in cable order; this never
                         changes the setup
  --replicas N           2 or more independent servers (Inkling, FP4-Local, or
                         paired FP8) behind a local gateway
  --pairs                With --replicas N: N two-Spark tensor-split servers on
                         2N Sparks instead
  --mtp N                Drafting depth (Inkling 0..7, default 7; FP4-Local
                         0..3, engine chooses; controller FP8 passes 2; 0 turns
                         drafting off). From a controller with
                         --diagnostic-unqualified-text, a two-Spark text service
                         takes 0..7 and loads 3 when this and MTP are unset; a
                         one-Spark plan uses its checkpoint default
  --context N            Context window in tokens, 4096 or more (Inkling default
                         524288; FP4-Local default 32768; hardware admission
                         decides ceiling)
  --output N             Output limit in tokens, up to context (Inkling default
                         16384; FP4-Local default 8192)
  --bind ADDR            HTTP listen socket address (for example 0.0.0.0:18080;
                         default 127.0.0.1:<port>)
  --disk-cache-dir PATH  Persistent NVMe disk prefix cache directory (Inkling
                         default $VADE_HOME/cache/prefix)
  --disk-cache-bytes N   Disk prefix cache budget in bytes (default
                         hardware-derived NVMe budget)
  --no-disk-cache        Disable persistent NVMe disk prefix cache
  --chats N              Concurrent FP8 chats, 1 or more (controller)
  --memory-bytes N       Memory budget per rank, in bytes
  --cache-bytes N        FP8 retained prompt cache, in bytes; 0 disables it.
                         Local FP4 and Inkling accept only 0 (prompt cache is on
                         by default)
  --decode-fuse MODE     on for one Spark by default; off disables the decode
                         kernel chain
  --diagnostic-unqualified-text
                         Legacy no-op for Inkling; enables two-Spark unqualified
                         text diagnostics
  --fast-prompts         Older option, kept for scripts; it has no effect
  --dry-run              Show what would happen; change nothing

Notes:
  - vade up inkling starts Inkling 2 Mini on one Spark with context 524288 (up
    to the checkpoint limit with --context), output 16384 (up to context),
    drafting depth 7 (--mtp 0 disables drafting), RAM prompt cache on
    (--cache-bytes 0 disables it), and persistent NVMe disk prefix cache on
    under $VADE_HOME/cache/prefix (--no-disk-cache disables it). Checks
    ~/models/thinkingmachines/Inkling-2-Mini first, then the read-only Hugging
    Face Hub cache.
  - Default: Qwen3.8 Flash-Next FP4-Local on one Spark.
  - FP4-Local runs on 1, 2 or 4 Sparks over RDMA, or as a layer chain of 3 or
    more Sparks over TCP. We have measured chains up to four Sparks.
  - FP8 runs on 2 or 4 Sparks, and the same request with the same settings gives
    the same token IDs on both. FP8 also starts on 6 Sparks, but its token IDs
    differ there, so 6 Sparks are not covered yet.
  - --sparks a,b checks each Spark over SSH, reads the cables, prints the chain,
    copies itself to each Spark and starts them. Type the Sparks in any order.
    Each name is what you type after ssh, or user@address.
  - A new list replaces the last setup: one line says so, the old file moves
    aside, and a running engine stops first. The same Sparks in the same order
    start with no new setup. After that, vade up alone starts the same Sparks,
    vade down stops them and vade chat opens a chat.
  - Local up and launch reuse saved limits. FP4-Local starts with context 32768
    and output 8192 (or the context if smaller). A memory refusal lowers a
    default or saved context to a smaller size from 32768, 16384, 8192 and 4096.
    The first size that starts is saved. A refused explicit --context is an
    error. Local --chats and positive --cache-bytes are refused; --cache-bytes 0
    disables retention.
  - Controller FP4 defaults match local ones on one Spark: context 32768, output
    8192 (or the context if smaller). On 2 or more Sparks in one group, a chain
    or a pair, the default context is 131072; if it does not fit in memory, up
    falls to 32768 and says so. --context 262144 requests a larger context. The
    engine still sets the chat count from context and memory.
  - Controller FP4 checks and passes on --chats and --cache-bytes, but its
    engine does not use them: it admits chats from memory and uses its own
    prefix cache setting.
  - A two-Spark text service (vade up --sparks 2 --diagnostic-unqualified-text)
    loads the predictor at depth 3 unless --mtp or MTP is set. When the model
    has no drafting layer, or free memory is too small for drafting, that start
    runs without drafting and says so. At loaded depth 3 or more, a greedy
    request of more than 64 tokens that names no drafting field is tried with
    drafting and keeps it only when it is faster. At loaded depth 1 or 2 that
    request decodes plain. A sampled request, a short request, mtp_depth 0 and
    several chats at once decode plain. --mtp 0 turns drafting off. Loading the
    predictor takes about 3.4 GB of device memory from the room for chats. One
    FP4 Spark leaves the depth to the engine. Controller FP8 passes --mtp 2 when
    unset. A request with draft=plain turns drafting off for that request;
    draft=strict asks for it when a predictor is loaded.
  - A diagnostic text plan that declares one Spark (vade up --sparks 1
    --diagnostic-unqualified-text) runs on one Spark with no transport, defaults
    to the checkpoint's max drafting depth (7 for Inkling 2 Mini; --mtp 0
    disables drafting), refuses a depth above its plan's max, and keeps prompt
    cache on unless --cache-bytes 0 is set. With --replicas N, each replica is
    one Spark; --replicas with --pairs is refused.
  - Two FP4-Local Sparks run the tensor split, the only two-Spark path for
    FP4-Local: both Sparks work on every token. It needs RDMA, so vade up
    refuses SEQPAR_RDMA=0 (TCP) for two FP4-Local Sparks. FP8 on two Sparks
    keeps its ring and may use TCP.
  - FP8 needs an FP8 config such as cli/examples/vade.conf. See
    docs/benchmarks.md.
  - --sparks N above 2 needs a setup with that many Sparks in cable order.
  - VADE_GROUP=NAME selects a [group NAME] from the config: its hosts in rank
    order, its own ownership record and its own local_port. A group must be an
    arc of the cabling: each host is cabled to the next, in rank order; a
    closing cable is not needed, so any run of neighbors on a ring works. Set
    the same VADE_GROUP for status, chat, logs and down. Groups in one layout
    can run at the same time. See docs/eight-sparks.md.
  - --replicas N starts one independent one-Spark server on each of the first N
    machines (or the N --hosts) and a local gateway on local_port; replica
    tunnels use the next N local ports. Each replica uses the FP4 defaults
    above. Use it when the model fits one Spark and many chats run at once;
    answers are the same on every replica.
  - --replicas N --pairs makes each replica a two-Spark tensor split: machines 1
    and 2 form the first pair, 3 and 4 the next, and each pair must share a
    fabric link. Only each pair's first machine gets a tunnel. The gateway keeps
    a chat's later turns on its pair while that pair has fewer than 8 requests
    in flight or is among the least busy, and gives each chat a stable prompt
    cache key. This is an option; the default four-Spark mode is unchanged. See
    docs/four-sparks.md.
  - One Spark needs no fabric. Linked Sparks use RDMA by default. SEQPAR_RDMA=0
    selects TCP, except for two FP4-Local Sparks. Keep VADE_CONFIG and VADE_HOME
    consistent through chat, status and down.
  - Only a running compute app or power draw of at least 30 W makes a GPU busy;
    a stale utilization reading is reported and never blocks.
